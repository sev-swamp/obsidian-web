# План 7. Автосохранение при редактировании (как в Obsidian / Заметках macOS)

Статус: проект (не начат)
Приоритет: высокий — UX-паритет с Obsidian; кнопка «Сохранить» —
главный источник потерянных правок (закрыл вкладку — потерял draft).
Зависимости: нет. Затрагивает NotePage/MarkdownEditor, API save,
history-адаптер.

## 1. Цель и мотивация

Сейчас правки живут только в React-state (`draft` в `NotePage.tsx`) до
явного нажатия Save/Cmd-S. Закрытие вкладки, переход по ссылке или
падение браузера теряют всё. Цель — редактор без кнопки «Сохранить»:
изменения уходят на сервер сами (debounce), пользователь видит только
индикатор «Сохранено / Сохранение… / Ошибка». Режимы «просмотр /
редактирование» остаются (в отличие от Apple Notes) — меняется только
судьба правок внутри режима редактирования.

## 2. Что уже есть и что мешает

| Компонент | Состояние | Роль в автосейве |
| --- | --- | --- |
| `SaveNote` + `baseHash` (optimistic lock, 409) | готово | защита от перезаписи чужих правок между автосейвами |
| `HashContent` / `contentHash` в GET note | готово | стартовый baseHash |
| Presence (кто редактирует) | готово | ранний сигнал о будущем конфликте |
| WS `file.changed` → invalidate `['note', path]` | готово | **мешает**: наш же автосейв дёргает refetch; внешняя правка при открытом редакторе никак не показана |
| `history.Record` — git-коммит на каждый save | готово | **мешает**: автосейв раз в ~2 c завалит историю коммитами |
| `TrackAuthorship` upsert'ит `updated`/`updated_by` | готово | контент на диске ≠ draft клиента → нельзя считать baseHash локально |

## 3. Дизайн

### 3.1 Фронтенд: hook `useAutosave`

Новый hook `apps/web/src/hooks/useAutosave.ts`; NotePage отдаёт ему
draft + baseHash и убирает кнопку Save (Cmd-S остаётся как «сохранить
немедленно» = flush).

Машина состояний: `idle → dirty → saving → idle | error | conflict`.

Правила:

- **Debounce 1.5–2 c** после последнего ввода + **maxWait ~10 c**
  (при непрерывной печати сохраняем не реже раза в 10 c).
- **Сериализация**: не более одного запроса в полёте. Если во время
  `saving` пришли новые правки — по завершении сразу новый save
  (флаг `pendingRef`), без параллельных PUT.
- **Цепочка baseHash**: после успешного save сервер возвращает новый
  `contentHash` (см. 3.2), он становится baseHash следующего save.
  Локально хеш считать нельзя — сервер дописывает frontmatter
  (`TrackAuthorship`).
- **Flush** (немедленное сохранение, минуя debounce): Cmd-S, выход из
  режима редактирования, unmount/смена маршрута, `visibilitychange →
  hidden`, `beforeunload` — последний через `fetch(..., { keepalive:
  true })` (JWT-заголовок доступен, в отличие от sendBeacon).
- **Ошибка сети**: индикатор «Не сохранено», retry с backoff
  (2s → 4s → 8s, max 30s); draft не трогаем.
- Индикатор — вместо кнопки Save в шапке: `saved` (галочка, гаснет),
  `saving…`, `error` (красный, кликабелен = retry), i18n-ключи в оба
  языка.

### 3.2 API: save возвращает contentHash

`handleSaveNote` сейчас отвечает пустым 200. Меняем:
`core.SaveNote` возвращает `(newHash string, err error)` — хеш
финального контента (после upsert'а frontmatter), посчитанный под тем
же `pathLock`. Handler отдаёт `{ "contentHash": "…" }`,
`client.ts.saveNote` возвращает его. Без этого клиенту пришлось бы
делать GET после каждого автосейва.

### 3.3 Конфликты: не модалка, а баннер

409 при автосейве — не повод для модального окна посреди печати.
На `conflict`:

1. автосейв останавливается (state `conflict`, правки копятся локально);
2. над редактором — жёлтый баннер «Заметку изменил X» с теми же
   действиями, что в текущем диалоге: «Перезаписать моим» (save с
   `currentHash` из 409) / «Взять их версию» (заменить draft).

Существующий модальный диалог конфликта остаётся только для явного
Cmd-S-flush (поведение как сегодня). Авто-merge (diff3) — вне scope,
v2.

### 3.4 Эхо своих сохранений и внешние правки

- WS-события уже несут `actor`. В `useVaultEvents` для `file.changed`
  добавить: если `actor === username` и путь совпадает с редактируемой
  заметкой — не инвалидировать `['note', path]` (свой автосейв, draft
  и так свежее). Инвалидации `recent`/`history` можно оставить.
- Внешняя правка (`actor !== username`) при открытом редакторе — не
  трогаем draft (защитит baseHash при следующем save), но можно сразу
  показать conflict-баннер, не дожидаясь 409.

### 3.5 История: squash-окно в history-адаптере

Автосейв раз в 2 c = сотни коммитов за сессию. Решение — коалесценция
на сервере, в `packages/history`:

- Если последний коммит HEAD сделан тем же `actor` для того же `path`
  с `action == "save"` и моложе окна `history.squashWindow`
  (конфиг, default `5m`, `0` = выключено) — новый Record **амендит**
  его: коммит создаётся с parent = HEAD^ и переставляет ветку
  (go-git: обычный Commit с `Parents: [head.ParentHashes...]` +
  обновление ref). Тайм-штамп и дерево — новые, сообщение то же.
- Иначе — обычный коммит (как сейчас).
- Итог: история выглядит как в Obsidian — «снимок сессии
  редактирования», а не каждое нажатие. Гарантии `Record`
  (blob-hash против HEAD, SkipStatus — см. gotchas) сохраняются.
- `mode: external` не трогаем — там Record и так no-op.

Альтернатива «отдельный endpooint автосейва без истории + checkpoint
при закрытии» отвергнута: падение вкладки оставит правки на диске без
ревизии, и это второй путь записи со своими багами.

### 3.6 Что не меняется

- Права: тот же `PUT /api/note/*path`, `notes:edit` + ACL.
- `TrackAuthorship`, событийная шина, поиск/бэклинки — обновляются на
  каждый автосейв как обычный save.
- Optimistic lock остаётся единственным механизмом согласования —
  никакого CRDT/OT (одиночный/малокомандный сценарий, presence
  предупреждает о параллельном редактировании).

## 4. Этапы

1. **Backend**: `SaveNote` → `(hash, error)`; ответ handler'а;
   squash-окно в history + конфиг + тесты (`go test ./...`).
2. **Frontend**: `useAutosave` (debounce/serialize/flush/retry),
   индикатор вместо кнопки, conflict-баннер, фильтр эха в
   `useVaultEvents`, i18n en+ru.
3. **Полировка**: `keepalive`-flush на beforeunload; настройка
   интервала debounce в prefs (опционально); упоминание в help
   (`apps/web/src/help/content.ts`, en+ru) и docs/syntax.md при
   необходимости.

## 5. Риски

- **go-git amend**: нет готового `--amend`; собираем коммит с
  родителями HEAD^ вручную — покрыть тестом «N автосейвов подряд → 1
  ревизия», «пауза > окна → новая ревизия», «другой actor → новая
  ревизия».
- **Гонка flush при unmount + смена маршрута**: flush должен читать
  актуальный draft из ref, не из замыкания.
- **`updated` в frontmatter**: на диске обновляется каждым автосейвом,
  в открытом draft — нет (так и сегодня); в v2 можно возвращать
  канонический контент в ответе save и мягко подменять frontmatter в
  редакторе.
